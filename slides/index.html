AI Agents 是什麼？

10 分鐘看懂：它和聊天機器人差在哪、由什麼組成、什麼時候該用

內容全部來自我自己建立的 LLM Wiki，每個要點都可以點開看原文引文

先給一個定義

不同機構的說法略有差別，但都指向同一件事：代替使用者去完成任務。

OpenAI

Agent 是替使用者獨立完成任務的系統。 S3

原文
Agents are systems that independently accomplish tasks on your behalf.
Google Cloud

Google Cloud 的定義：用 AI 追求目標、代替使用者完成任務的軟體系統。 S6

原文
AI agents are software systems that use AI to pursue goals and complete tasks on behalf of users.
多了什麼能力

Agent 具備推理、規劃與記憶，並有一定程度的自主性，可以做決策、學習與調整。 S6

原文
They show reasoning, planning, and memory and have a level of autonomy to make decisions, learn, and adapt.

白話補充（我的話，不是來源）一般的聊天機器人是你問一句、它答一句。Agent 的重點是「替你把事情做完」。

Wiki：ai-agent#AGENT-1、ai-agent#AGENT-2、ai-agent#AGENT-3

Agent 由什麼組成（一）：三個核心元件

OpenAI 的指南把 Agent 拆成三塊，可以把它想成「大腦、手、規則」。

模型（大腦）

第一個元件是模型：負責 Agent 的推理與決策。 S3

原文
The LLM powering the agent’s reasoning and decision-making
工具（手）

第二個元件是工具：Agent 用來採取行動的外部函式或 API。 S3

原文
External functions or APIs the agent can use to take action
指令（規則）

第三個元件是指令：明確規範 Agent 行為的準則與護欄。 S3

原文
Explicit guidelines and guardrails defining how the agent behaves
補充主張

OpenAI 指出，最基本的 Agent 由三個核心元件組成。 S3

原文
In its most fundamental form, an agent consists of three core components:

白話補充（我的話，不是來源）「大腦、手、規則」是我為了好記加的比喻，不是原文用語。

Wiki：components#COMP-2、components#COMP-3、components#COMP-4、components#COMP-1

Agent 由什麼組成（二）：規劃、記憶、工具

Lilian Weng 從另一個角度拆解：LLM 是大腦，周圍有規劃、記憶、工具使用這幾種能力。

規劃

規劃：Agent 把大任務拆成較小、可處理的子目標。 S2

原文
The agent breaks down large tasks into smaller, manageable subgoals, enabling efficient handling of complex tasks.
短期記憶

短期記憶很短而且有限，因為受到 Transformer 上下文視窗長度的限制。 S2

原文
It is short and finite, as it is restricted by the finite context window length of Transformer.
長期記憶

長期記憶是 Agent 查詢時可以取用的外部向量資料庫，能快速檢索。 S2

原文
Long-term memory as the external vector store that the agent can attend to at query time, accessible via fast retrieval.
工具使用

替 LLM 配上外部工具，可以大幅擴充模型的能力。 S2

原文
Equipping LLMs with external tools can significantly extend the model capabilities.
補充主張

Lilian Weng 把 Agent 系統描述成：LLM 是大腦，再搭配幾個關鍵元件。 S2

原文
LLM functions as the agent’s brain, complemented by several key components

白話補充（我的話，不是來源）這一頁和上一頁是不同作者切的角度，但都包含 LLM 和工具。

Wiki：components#COMP-6、components#COMP-7、components#COMP-8、components#COMP-9、ai-agent#AGENT-8

Agent 怎麼運作：想、做、看結果

Agent 不是一次回答完，而是在迴圈裡反覆進行。

1推理
→
2行動
→
3環境回饋
↺ 根據回饋，再回到「推理」，直到結束

迴圈在做什麼

ReAct 讓語言模型交錯地產生語言推理過程與文字動作。 S5

原文
ReAct enables language models to generate both verbal reasoning traces and text actions in an interleaved manner.

Agent 在每一步都要從環境取得「真實回饋」（ground truth），用來判斷進度。 S1

原文
gain "ground truth" from the environment at each step

迴圈的出口

迴圈裡通常也會設定停止條件。 S1

原文
it's also common to include stopping conditions

Agent 可以在檢查點或遇到阻礙時暫停，等待人類回饋。 S1

原文
Agents can then pause for human feedback at checkpoints or when encountering blockers.
補充主張

Agent 通常只是 LLM 在迴圈裡，根據環境回饋來使用工具。 S1

原文
They are typically just LLMs using tools based on environmental feedback in a loop.

在 ReAct 之前，方法通常只讓模型做其中一件事：推理，或執行任務動作。 S5

原文
Previous methods prompt language models (LM) to either generate self-conditioned reasoning traces or task-specific actions.

ReAct 的表現優於只產生動作的模型，並和思維鏈（CoT）推理的表現相當。 S5

原文
ReAct outperforms vanilla action generation models while being competitive with chain of thought reasoning (CoT) performance.

白話補充（我的話，不是來源）迴圈要有出口：到達停止條件就結束，遇到問題就停下來問人。

Workflow 和 Agent 差在哪

兩者都用 LLM 和工具，差別在「流程是誰決定的」。

Workflow：流程是人寫好的

Workflow 是用預先寫好的程式路徑，把 LLM 和工具串起來的系統。 S1

原文
Workflows are systems where LLMs and tools are orchestrated through predefined code paths.

Agent：流程由模型決定

Agent 則是由 LLM 動態決定自己的流程與工具使用方式的系統。 S1

原文
Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage

Agent 從使用者的指令或互動討論開始工作。 S1

原文
Agents begin their work with either a command from, or interactive discussion with, the human user.
補充主張

Anthropic 把這些不同的做法統稱為 agentic systems。 S1

原文
we categorize all these variations as agentic systems

白話補充（我的話，不是來源）如果每次的步驟都一樣，用 Workflow 就好；步驟會隨情況變，才需要 Agent。

Wiki：workflow-vs-agent#WA-1、workflow-vs-agent#WA-2、workflow-vs-agent#WA-5、workflow-vs-agent#WA-3

五種常見的 Workflow 模式

Anthropic 把 LLM 串起來的常見做法，整理成五種。

提示鏈

提示鏈（prompt chaining）：把任務拆成一串步驟，每次 LLM 呼叫處理前一次的輸出。 S1

原文
Prompt chaining decomposes a task into a sequence of steps, where each LLM call processes the output of the previous one.
路由

路由（routing）：先分類輸入，再導向專門的後續任務。 S1

原文
Routing classifies an input and directs it to a specialized followup task.
平行化

平行化（parallelization）：LLM 可以同時處理一個任務，再用程式彙整輸出。 S1

原文
LLMs can sometimes work simultaneously on a task and have their outputs aggregated programmatically.
協調者—工作者

協調者—工作者（orchestrator-workers）：由一個中心 LLM 動態拆解任務、分派給工作者 LLM。 S1

原文
a central LLM dynamically breaks down tasks, delegates them to worker LLMs
評估者—優化者

評估者—優化者（evaluator-optimizer）：一個 LLM 產生回應，另一個在迴圈中給出評估與回饋。 S1

原文
In the evaluator-optimizer workflow, one LLM call generates a response while another provides evaluation and feedback in a loop.

白話補充（我的話，不是來源）這五種是 Anthropic 這篇文章的分類，不是業界唯一標準。

Wiki：workflow-patterns#PAT-1、workflow-patterns#PAT-2、workflow-patterns#PAT-3、workflow-patterns#PAT-4、workflow-patterns#PAT-5

任務變複雜：多個 Agent 怎麼分工

OpenAI 與 Google 都描述了從單一 Agent 到多 Agent 的做法。

單一 Agent

單一 Agent 系統：一個配備工具與指令的模型，在迴圈中執行工作流程。 S3

原文
Single-agent systems, where a single model equipped with appropriate tools and instructions executes workflows in a loop
管理者模式

管理者模式：一個中央「管理者」Agent 透過工具呼叫，協調多個各自負責特定任務的專門 Agent。 S3

原文
A central “manager” agent coordinates multiple specialized agents via tool calls, each handling a specific task or domain.
交接

交接（handoff）是單向轉移，讓一個 Agent 把工作委派給另一個 Agent。 S3

原文
Handoffs are a one way transfer that allow an agent to delegate to another agent.
補充主張

多 Agent 系統由多個 Agent 合作或競爭，來達成共同目標或各自的目標。 S6

原文
Multiple AI agents that collaborate or compete to achieve a common objective or individual goals.

白話補充（我的話，不是來源）先從單一 Agent 開始，不夠用再拆。

Wiki：multi-agent#MULTI-1、multi-agent#MULTI-2、multi-agent#MULTI-3、multi-agent#MULTI-4

什麼時候該用？代價是什麼？

Agent 不是預設答案。兩家公司的指南都先提醒你確認是否真的需要。

先確認需不需要

很多應用只要把單次 LLM 呼叫搭配檢索與範例調好，通常就夠了。 S1

原文
For many applications, however, optimizing single LLM calls with retrieval and in-context examples is usually enough.

OpenAI 建議：決定做 Agent 之前，先確認你的使用情境清楚符合條件。 S3

原文
Before committing to building an agent, validate that your use case can meet these criteria clearly.

如果不符合條件，確定性的（寫死規則的）方案可能就足夠了。 S3

原文
Otherwise, a deterministic solution may suffice.

要付出的代價

Agent 的自主性代表更高的成本，以及錯誤會累積的可能。 S1

原文
The autonomous nature of agents means higher costs, and the potential for compounding errors.

Agentic system 常用延遲與成本，換取更好的任務表現。 S1

原文
Agentic systems often trade latency and cost for better task performance

實務上，許多 Agent 示範程式的重點，是在解析模型的輸出。 S2

原文
Consequently, much of the agent demo code focuses on parsing model output.
補充主張

Agent 的自主性，使它適合在可信任的環境中擴大處理任務的規模。 S1

原文
Agents' autonomy makes them ideal for scaling tasks in trusted environments.

設計 Agent 時要保持簡單。 S1

原文
Maintain simplicity in your agent's design.

白話補充（我的話，不是來源）能用固定規則解決的，就不要為了「聽起來厲害」硬做 Agent。
